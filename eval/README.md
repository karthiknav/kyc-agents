# KYC Eval

End-to-end pipeline evaluation using real AI output, LLM-as-judge, and Langfuse dataset experiments.

Runs the full 4-agent KYC crew against seeded test cases and scores each run with:
- **decision-accuracy** — exact match on APPROVED / ESCALATED
- **decision-justification** — GEval LLM judge: does `reason[]` logically follow from what the agents actually found?

---

## Folder structure

```
eval/
  fixtures/
    all_clear/          case.json + drop document(s) here
    document_mismatch/  case.json + drop document(s) here
    sanction/           case.json + drop document(s) here
    pep/                case.json + drop document(s) here
  golden_dataset.json   expected outcomes per fixture
  seed.py               uploads docs to S3 + creates DynamoDB records
  run_eval.py           runs crew + LLM judge + posts to Langfuse
  requirements.txt
  case_ids.json         generated by seed.py — do not commit
```

---

## Prerequisites

- crew `.venv` active with crew dependencies installed
- Mock service running (BRP + PEP URLs already set in `crew/.env`)
- AWS credentials configured
- Langfuse credentials in `crew/.env`

---

## Step 1 — Install `deepeval`

```bash
cd crew
source .venv/Scripts/activate
uv pip install deepeval
```

---

## Step 2 — Drop mock documents into fixture folders

Place at least one image or PDF per fixture folder:

```
eval/fixtures/all_clear/          ← passport image(s) for Jan de Vries
eval/fixtures/document_mismatch/  ← passport image(s) for Maria Jansen
eval/fixtures/sanction/           ← passport image(s) for Ahmed Al-Rashid
eval/fixtures/pep/                ← passport image(s) for Willem van den Berg
```

Supported formats: `.png`, `.jpg`, `.jpeg`, `.pdf`, `.tiff`

---

## Step 3 — Seed DynamoDB + S3

Run from the repo root:

```bash
python -m eval.seed
```

Uploads documents to S3 and creates a DynamoDB case record per fixture.
Writes `eval/case_ids.json` (fixture name → caseId). Safe to re-run — existing IDs are reused.

If you already have cases in DynamoDB, skip this step and write `case_ids.json` manually:

```json
{
  "all_clear":         "your-existing-case-id",
  "document_mismatch": "your-existing-case-id",
  "sanction":          "your-existing-case-id",
  "pep":               "your-existing-case-id"
}
```

---

## Step 4 — Seed the Langfuse dataset (once)

```bash
python -m eval.run_eval --seed-dataset
```

Creates the `kyc-pipeline-accuracy` dataset in Langfuse with 4 items.
Go to **Langfuse → Datasets → kyc-pipeline-accuracy** to verify.

---

## Step 5 — Run an experiment

```bash
DEEPEVAL_TELEMETRY_OPT_OUT=YES \
python -m eval.run_eval \
  --run-experiment \
  --experiment-name "openai"
```

Runs the full crew on all 4 cases (~2–5 min per case), scores with exact-match + GEval judge,
and posts results to Langfuse.

Re-run with a new `--experiment-name` after any model or prompt change to get a side-by-side comparison.

---

## Step 6 — View results in Langfuse

Go to **Datasets → kyc-pipeline-accuracy → Runs**.

| fixture | decision-accuracy | decision-justification |
|---|---|---|
| all_clear | 1.0 | 0.87 |
| document_mismatch | 1.0 | 0.92 |
| sanction | 1.0 | 0.88 |
| pep | 1.0 | 0.81 |

Each `--experiment-name` appears as a separate column for comparison.

## Notes

- **all_clear uses a common Dutch name** ("Jan de Vries") so DuckDuckGo adverse media search may occasionally return results for other people with the same name, causing the crew to correctly return ESCALATED instead of APPROVED. This is expected behaviour.
- `case_ids.json` is generated — do not commit it.
- All eval commands must be run from the **repo root**, not from inside `eval/`.

---

## Troubleshooting

| Error | Fix |
|---|---|
| `case_ids.json not found` | Run `python -m eval.seed` first |
| `Dataset is empty` | Run `python -m eval.run_eval --seed-dataset` first |
| `No module named crew` | Run from repo root, not from inside `eval/` |
| `BRP/PEP connection error` | Check mock service is reachable at the URL in `crew/.env` |
| `deepeval` JSON parse error | Add `DEEPEVAL_TELEMETRY_OPT_OUT=YES` to the command |
